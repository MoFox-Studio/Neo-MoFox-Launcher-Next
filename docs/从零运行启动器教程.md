# 从零开始从源码运行 Neo-MoFox Launcher 教程

> 适用对象：测试群成员。跟着本教程，不需要任何开发经验，也可以从源码把启动器跑起来。
> 全程约 10~20 分钟，取决于网络速度。

---

## 1. 这是什么

Neo-MoFox Launcher 是一个桌面启动器，用来安装、运行和监控 Neo-MoFox QQ 机器人实例（支持 NapCat / SnowLuma 平台）。

本教程教你**从源码运行**，也就是直接跑「开发模式」，而不是安装打包好的程序。这样测试的都是最新的代码，但**不要用于日常使用**，仅供测试体验。

---

## 2. 环境准备

### 2.1 系统要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11（64 位）或主流 Linux 发行版 |
| Node.js | **18 或更高**（推荐 22 LTS，项目 CI 用的就是 22） |
| npm | 随 Node.js 一起安装，无需单独配置 |
| 网络 | 能访问 GitHub / npm 仓库（国内环境建议先配好 npm 镜像，见 3.1） |

> macOS 目前平台适配层未覆盖，暂不推荐用 macOS 测试。

### 2.2 安装 Git（必装，用来下载源码）

- **Windows**：从 https://git-scm.com/download/win 下载安装，一路「Next」默认即可。安装后按 `Win + R` 输入 `cmd` 回车，输入 `git --version` 能看到版本号即安装成功。
- **Linux**：`sudo apt install git`（Debian/Ubuntu）或 `sudo pacman -S git`（Arch）等。

### 2.3 安装 Node.js

从官网下载安装 LTS 版本：

- **Windows**：https://nodejs.org/zh-cn/download ，下载「Windows 安装包 (.msi)」，一路默认安装。
- **Linux**：建议用 nvm 或发行版包管理器安装 Node 22。

安装完成后打开命令行验证：

```bash
node -v
npm -v
```

两条命令都能输出版本号（Node 为 18+）就说明环境 OK。

> Windows 用户建议使用 **PowerShell** 或 **Windows Terminal** 执行下面的命令。

## 3. 开始之前：npm 镜像加速（可选但强烈建议）

国内网络访问 npm 官方源较慢，建议换成淘宝镜像（只影响 npm 下载，不影响启动器本身）：

```bash
npm config set registry https://registry.npmmirror.com
```

之后所有 `npm install` 都会走镜像，速度会快很多。

---

## 4. 下载源码

```bash
git clone https://github.com/MoFox-Studio/Neo-MoFox-Launcher-Next.git
cd Neo-MoFox-Launcher-Next
```

> 如果克隆失败，多半是网络问题，可尝试代理或用 GitHub 镜像站。

---

## 5. 安装依赖

```bash
npm install
```

首次安装需要下载较多依赖（含 Electron 本体），**耐心等待**，几分钟到十几分钟不等。

安装完成后，检查一下 `node_modules` 目录已经生成。

> 提示：项目内 `.npmrc` 里限制了依赖的自动构建脚本白名单（`electron` / `node-pty` 等），这是安全设计，**不要修改**。

### 5.1 Windows 下的常见坑：原生模块 node-pty

`node-pty` 是终端功能依赖的**原生模块**（需要编译），两个典型报错：

- `node-gyp` / `gyp ERR!`：说明缺少编译工具链，需要安装：
  ```bash
  npm install --global windows-build-tools
  ```
  或手动安装 [Visual Studio Build Tools](https://visualstudio.microsoft.com/zh-hans/downloads/)（勾选「使用 C++ 的桌面开发」）。
- 依赖装好后终端功能异常：对 node-pty 执行重建：
  ```bash
  npm run rebuild:native
  ```

## 6. 运行启动器

### 方式 A：完整开发模式（推荐）

```bash
npm run dev
```

首次运行需要编译 main / preload / renderer 三端，稍等片刻后会**自动弹出 Electron 窗口**。

启动成功后：

- 命令行会持续输出日志（**不要关掉这个命令行窗口**，关掉就等于退出启动器）；
- 修改代码会热更新，无需手动重启；
- 看到类似 `vite v6.x ready` 和 Electron 窗口出现即成功。

### 方式 B：浏览器预览模式（无 Electron 环境时）

如果本机装不上 Electron（比如网络受限），可以在浏览器里预览完整界面：

```bash
npm run dev:demo
```

然后浏览器打开 `http://localhost:5199`。此模式使用内置 Mock 数据，**不能真正启停实例**，只适合看 UI。

---

## 7. 首次进入启动器

1. 首次启动会进入 **OOBE 引导页**，自动检测 Python / uv / Git 等环境信息，一路下一步即可。
2. 进入主界面后，可以通过**安装向导**安装 NapCat 或 SnowLuma 平台并创建实例，也可以从旧版启动器数据目录一键迁移。

> 实例安装会从 GitHub Release 下载平台文件，需要能访问 GitHub。如失败可换镜像重试。

---

## 8. 常见问题排查

| 现象 | 解决方法 |
| --- | --- |
| `npm run dev` 报 `port 5199 in use` | 端口被占用，找到占用进程关掉，或重启电脑 |
| Electron 窗口一闪而过 / 白屏 | 等 Vite 编译完成后再启动一次；或先删掉 `dist/` 和 `node_modules` 重新来一遍 |
| node-pty 相关报错 | 见 5.1，执行 `npm run rebuild:native` |
| 安装依赖超时失败 | 确认已配 npm 镜像（见第 3 节），删掉 `node_modules` 和 `package-lock.json` 后重装 |
| 拉取 GitHub Release 失败 | 换平台镜像或在设置里调整镜像源后重试 |
| 改了代码不生效 | 正常应为热更新；若异常，关闭命令行窗口后重新 `npm run dev` |
| 想彻底重来 | 删除 `node_modules`、`dist` 目录，重新执行 `npm install && npm run dev` |

## 9. （进阶，可选）打包成安装程序

测试完成后如果不想每次开命令行，也可以本地打包出安装包：

```bash
# 构建 + 重建原生模块 + 打目录包（输出到 release/）
npm run pack:dir

# 打 Windows 安装包（NSIS + 便携版）
npm run package:win
```

## 10. 常用命令速查

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 完整开发模式，弹出 Electron 窗口 |
| `npm run dev:demo` | 浏览器预览模式（Mock 数据） |
| `npm test` | 运行单元测试 |
| `npm run typecheck` | 三端 TypeScript 类型检查 |
| `npm run lint` | ESLint 代码检查 |
| `npm run rebuild:native` | 重建原生模块（node-pty 出问题时用） |
| `npm run pack:dir` / `npm run package:win` | 本地打包 |
